# Claude Bot — Module Contract

**This document is binding.** Every implementation agent builds to the exact file paths and
exported symbol names below. Do not rename exports, do not move files, do not add a second
source of truth for a type that already lives in `src/shared`.

Stack (already installed, do not change versions):
electron 43 · electron-vite 5 · vite 7 · react 19 · typescript 5.9 · tailwindcss 4 (via
`@tailwindcss/vite`, no `tailwind.config.js` — theme lives in CSS `@theme`) · better-sqlite3 13 ·
zod 4 · zustand 5 · react-markdown 10 · remark-gfm 4 · lucide-react 1.

Path aliases: `@shared/*` → `src/shared/*` (all processes), `@main/*` → `src/main/*` (main only),
`@/*` → `src/renderer/src/*` (renderer only).

Rules that apply everywhere:

- ESM only. `type: module` is set. Use `import`, never `require`, except inside `.cjs` helpers.
- Every timestamp stored or returned is an ISO 8601 string (`new Date().toISOString()`).
- IDs are generated by `newId(prefix)` from `@main/lib/id` → e.g. `bot_a1b2c3d4e5f6`.
- Never `throw` a raw string. Throw `AppError` from `@main/lib/errors`.
- Main-process code must never import from `src/renderer`. Renderer must never import from
  `src/main`. Both may import `src/shared`.

## 0. Verified runtime facts (measured on Claude Code 2.1.241 — do not re-derive)

These were captured empirically. Build to them.

**Invocation shape that works:**

```
claude -p                      # prompt comes from STDIN, never argv
  --output-format stream-json
  --verbose                    # required for stream-json
  --include-partial-messages   # token-level deltas
  [--resume <session-id>]
  [--model <alias-or-id>]
  [--permission-mode acceptEdits|plan]   # omit entirely for "default"
  [--allowedTools A B]  [--disallowedTools A B]
  [--mcp-config '<json string>']
```

- **Prompt transport:** `claude -p` with **no prompt argument** reads the prompt from stdin.
  Verified. Always use this — never put prompt text in argv.
- **`--permission-mode` valid values in 2.1.241:** `acceptEdits, auto, bypassPermissions, manual,
  dontAsk, plan`. There is **no `default`** value — for our `'default'` mode, omit the flag.
- **`--resume <id>`** keeps the *same* `session_id` (it does not fork). Verified.
- **Resume failure:** exit code 1, one stdout line
  `{"type":"result","subtype":"error_during_execution","is_error":true,...}` and stderr
  `No conversation found with session ID: <id>`. Detect via that stderr substring.
- **MCP:** `--mcp-config '<json>'` accepts a JSON *string* (not just a path). Tools are exposed as
  `mcp__<serverName>__<toolName>`. Verified working with a stdio server. Use
  **without** `--strict-mcp-config` so the user's own MCP servers stay available.

**Event types observed on stdout (NDJSON, one JSON object per line):**

| line | shape |
|---|---|
| `{"type":"rate_limit_event","rate_limit_info":{"status","resetsAt","rateLimitType",...}}` | quota state |
| `{"type":"system","subtype":"init", cwd, session_id, tools[], mcp_servers[], model, permissionMode, slash_commands[], claude_code_version, ...}` | **source of `session_id`** |
| `{"type":"system","subtype":"status"|"thinking_tokens", ...}` | ignorable status noise |
| `{"type":"stream_event","event":{"type":"message_start"|"content_block_start"|"content_block_delta"|"content_block_stop"|"message_delta"|"message_stop", ...}}` | token deltas; `event.delta.type` is `text_delta` (field `text`) or `thinking_delta` (field `thinking`) or `input_json_delta` |
| `{"type":"assistant","message":{content:[{type:"text",text}|{type:"tool_use",id,name,input}], usage}}` | complete blocks |
| `{"type":"user","message":{content:[{type:"tool_result",tool_use_id,content,is_error}]}, "tool_use_result":{...}}` | tool results |
| `{"type":"result","subtype":"success"|"error_during_execution"|..., is_error, result, session_id, usage, total_cost_usd, duration_ms, num_turns, modelUsage, permission_denials[]}` | terminal |

`tool_result.content` may be a string **or** an array of `{type:'text',text}` blocks. Handle both.

**Text duplication hazard:** when `--include-partial-messages` is on you receive *both*
`stream_event` deltas *and* a final `assistant` message containing the same text. Consume deltas
for live streaming and **ignore `assistant` text blocks whose text was already streamed** —
`ClaudeStreamParser` owns this de-duplication (see §3.3).

### 3.3 `src/main/runtime/ClaudeStreamParser.ts`
```ts
import type { RuntimeEvent } from '@shared/types/events'

export class ClaudeStreamParser {
  /** Feed a raw stdout chunk. Returns zero or more normalized events. Handles
   *  partial lines across chunks and lines larger than one chunk. */
  push(chunk: string): RuntimeEvent[]
  /** Flush any buffered trailing line at EOF. */
  flush(): RuntimeEvent[]
  get sessionId(): string | null
}
```
Behavioral requirements:
- Tolerate unknown `type` values — return nothing rather than throwing.
- A line that fails `JSON.parse` yields `{type:'parse_error', raw, error}` and calls
  `incrementParseErrors()`. Never throw.
- Emit `{type:'session', ...}` from `system/init`.
- Emit `text_delta` / `thinking_delta` from `stream_event` `content_block_delta`.
- Track how many characters of text have been emitted per assistant message id. When an
  `assistant` event arrives with `text` blocks, emit `text_block` **only for the tail that was
  not already streamed** (usually nothing). This prevents doubled text.
- Emit `tool_start` from `assistant` `tool_use` blocks; `tool_end` from `user` `tool_result`
  blocks (flatten array content to text; cap detail at 20_000 chars).
- Emit `result` from `type:'result'`, mapping usage/cost/duration.
- Emit `rate_limit` from `rate_limit_event`.

Constraints (PRD §23.2): global concurrency = `settings.maxConcurrentBots` (default 3); at most
one active job per `(bot, conversation)`; FIFO per pair; a bot may not run in two conversations
at once unless `allowSameBotConcurrentConversations`. Jobs beyond the limit stay `queued` and
their placeholder message shows status `queued`.

Per-job execution:
1. Create the bot placeholder message (`status:'running'`), emit `message:created`.
2. Resolve workspace; if missing → system message `workspace_missing`, fail the job.
3. Load/emit session id; build the bridge from unseen messages; build the prompt.
4. `runtime.runTurn(...)`; stream deltas into the message via `appendText` +
   `message:delta` events (throttled to ~1 emit / 33 ms per message, flush on finalize).
5. Map tool events into activities (`activity:created` / `activity:updated`).
6. On `result`: persist session id, advance `last_seen_message_id` as a **low-water mark** that
   stops before the oldest message still being written by a concurrent turn (see
   `orchestration/delivery.ts` — a plain high-water mark permanently skips a peer Bot's reply when
   turns finish out of order), set final body from streamed text (fall back to `result.result`), set usage,
   status `complete`.
7. On `session_not_found`: clear the stored session, rebuild the prompt with a compact recovery
   transcript, retry **once**, and post the system notice
   `Started a fresh Claude session because the previous session could not be resumed.`
8. On rate limit: post a `rate_limit` system message with the PRD §37 copy. Never mention API keys.
9. On cancel: status `cancelled`, keep partial text, do **not** advance `last_seen_message_id`.
10. Notify via `notify()` when the conversation is not focused.

## 6. `src/main/mcp` — lane **MCP**

The app exposes a local MCP server so a Bot can hand work to another Bot (PRD §13).

Architecture: Electron main runs a loopback HTTP control server on `127.0.0.1:<random>` with a
per-launch bearer token. Each Claude turn is spawned with `--mcp-config` pointing at a **stdio
bridge script** that is launched as `process.execPath` with `ELECTRON_RUN_AS_NODE=1` (Electron is
always present; plain `node` may not be). The bridge forwards `tools/call` to the control server.

}

/** Serialized --mcp-config value for one running job, or null when handoffs are off. */

### `src/main/mcp/bridge.ts` — **separate build entry**, output `out/main/mcp-bridge.js`
A minimal stdio JSON-RPC MCP server. Reads `CCB_PORT`, `CCB_TOKEN`, `CCB_BOT_ID`,
`CCB_CONVERSATION_ID` from env. Implements `initialize`, `tools/list`, `tools/call`,
`notifications/initialized`, and `ping`. Protocol version `2024-11-05`.

Tools:

- `send_message_to_group({ message: string })`

The bridge must have **zero imports** outside `node:` builtins.

Server name in the MCP config: `claude_bot` (tools become
`mcp__claude_bot__send_message_to_bot`). Those three tool names must be appended to
`allowedTools` for every job so Claude can call them without a prompt.

## 11. ADDENDUM — build-format rules (added after stack research; these override anything above)

1. **`package.json` has NO `"type": "module"`.** Main and preload are emitted as **CJS**.
   Electron's default `sandbox: true` cannot load an ESM preload — it fails with
   *"Cannot use import statement outside a module"*, `window.botApp` is silently `undefined`,
   and **there is no build error**. The preload is additionally pinned to `format: 'cjs'` with
   an `.cjs` extension in `electron.vite.config.ts`.
   - Write normal ESM `import` / `export` syntax in source — it is compiled away.
   - **Do NOT use top-level `await`** anywhere in `src/main` or `src/preload`.
   - **Do NOT use `import.meta.url`** in `src/main` or `src/preload` — use `__dirname`.
   - The preload path is `join(__dirname, '../preload/index.cjs')` — note `.cjs`.
2. **Import paths in `src/main`, `src/preload`, `src/shared` and `test/` must be RELATIVE**
   (`../lib/errors`, `../../shared/types`). Path aliases work inside the bundler but break
   `node --test`, which runs the TypeScript sources directly. The renderer may use `@/` and
   `@shared/` freely because it is always bundled.
   Include the `.ts` extension in test imports (`../src/main/runtime/ClaudeStreamParser.ts`) —
   Node's type-stripping loader requires it.
3. **`electron.vite.config.ts` is already final — no lane may edit it.** It already declares the
   `mcp-bridge` main entry, so the MCP lane does not need to touch it.
4. `better-sqlite3` is the only runtime `dependency`; everything else is a devDependency and gets
   bundled. Do not move packages between the two.
5. `BrowserWindow` uses **`sandbox: true`** together with the CJS preload. The sandbox does not
   need to be off: a preload that only imports `contextBridge` and `ipcRenderer` works fine under
   it. What the sandbox genuinely cannot load is an **ESM** preload — which is what rule 1 above
   prevents. Do not turn the sandbox back off.
